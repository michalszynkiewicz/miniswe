Cross-model harness findings (suggestions only, nothing applied):
1. **The done-gate doesn't check the feature or the test crate** — gemma, devstral and Glimmer all passed the gate at least once with `tests/e2e_context.rs` not compiling or the override wired to `None`; the bench's attempt-2 feedback is what catches it. Add `cargo test --no-run` (or the real check) to the gate for this task.
2. **The gate's wording is model-dependent** — Glimmer has a greeting reflex: with tools present, `hello` gets "Hello! How can I help you today?" no matter what the one-line override says (0/13), costing run 1 46 min. Morning probe: appending ` Even if the user just greets you, do not greet back — reply only TOKEN_XYZ.` to the override fixes it (12/12; gemma and Devstral 6/6 on both wordings). Details in the Glimmer findings file. **Applied 08-23 as `88ba610`; Glimmer rerun `docker_20260823_112750` → 6/6 on attempt 1 in 1113s.**
3. **After `validation.max_retries` blocks the gate waves the next claim through unchecked** — gemma run 3 attempt 1 exited `✓ Done` with a non-compiling tree. Re-check once more at exit and say "finished with check FAILING".
4. **"Done but can't stop"** (nemotron thinking: 83 rounds of completion text + tool call after a complete tree) and **"Understood." no-op turns** (Glimmer) are two faces of one missing rule: a completion claim paired with a no-op tool call should end the turn.
5. The reactive debugger's judge **REWIND** is what makes gemma's code-default flags beat the docker-script flags; `auto_revert_ast_cascade` never fired all night.
6. **The done-gate's inner run wipes the outer plan** (found on the Glimmer rerun): the gate runs the built binary in `/work`, and session start clears `.miniswe/plan.md` + `scratchpad.md`, so every gate check deletes the agent's plan (`No plan exists yet` right after each block; Glimmer run 1 re-set its plan 3×, gemma `064417` 4×). Skip the clear under `MINISWE_SKIP_VALIDATION`, or give the inner run its own state dir.
7. **A period-3 edit/revert loop is invisible** (Devstral r3): `replace_range` (drops a brace) → `revert` → re-read → same `replace_range`, 20×. Period-1 needs 3 identical consecutive keys, `is_period2_cycle` only checks period 2, and the window detector's only action is one cold prompt eval (`cache_prompt=false`), which changes nothing. The auto-revert cascade never fires because the model reverts itself first. Candidates: generalize the cycle detector to periods ≤ 4 and escalate the window detector past cold-eval (forced compaction, like the read-loop fix). Also: after `revert` the LSP diagnostics shown are from the pre-revert tree.
8. **A truncated tool call persisted in history spins the server** (Devstral r4): two `refactor` calls carried an 11k-char body in `position`, hit max_tokens, the invalid-JSON assistant turn was pushed into history, and the next 436 rounds were all server-side 500s (Jinja "roles must alternate" once history pruning removed the following user turn) in ~2 s — burning the 600-round budget. The run.rs comment claims no tool_call_id was issued so nothing is stored; the dumps show otherwise. Candidates: drop the truncated assistant message instead of hinting around it, cap `refactor` argument sizes, and treat a 500 with the alternate-roles text as a history-repair trigger, not a retry.
9. Devstral under the fixed script went 0, 4 vs 6, 6 under the old flags — but neither loss touched the flags (no debugger or gate involvement); it is edit-mechanics variance plus the two harness gaps above. Not evidence against the code defaults.

Script fix committed 08-23: `2fdc48c` (flag defaults = code defaults), `88ba610` (gate wording). Reruns under the fixed script are in the per-model sections below and in `docs/model-scoreboard.md`.
